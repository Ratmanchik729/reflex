# REFLEX

**Автоматический контр-удар для Attack-Defense CTF.** Пассивно перехватывает эксплойт в
трафике своего вулнбокса, определяет команду атакующего, подменяет flag-id на актуальный
у жертвы, воспроизводит эксплойт по боксу атакующего и сдаёт добытый флаг.

Только Python stdlib — ничего не нужно ставить (`pip install` не требуется). Запускается
одной командой от root.

```
          атакующий ──эксплойт──►  наш вулнбокс
                                        │  REFLEX сниффит трафик (AF_PACKET / NFLOG)
                                        │  видит свой флаг в ответе  ⇒  атака подтверждена
                                        ▼
   наш флаг у атакующего ◄──реплей с подменённым flag-id── REFLEX ──► сдаём флаг геймсерверу
```

## Возможности

- **Пассивный захват.** Raw-сокет `AF_PACKET` (в бою — `iptables -j NFLOG`), сервис не
  трогается, нулевая добавочная задержка.
- **Подтверждение по ground truth.** Контр-удар только когда наш флаг реально виден в
  ответе нашего сервиса — без ложных срабатываний.
- **Самообучение паттернов.** REFLEX сам находит flag-id в перехваченном запросе
  (query / path / body) и строит шаблон со слотом `{FLAGID}`; подстановка идёт в слот,
  а не в хардкод.
- **Классификация техник.** IDOR → подмена flag-id; SQLi / LFI / PHP / cmdi → реплей
  пейлоада как есть; XSS и прочее без утечки флага → поток intel «кто чем щупает».
- **Арсенал.** Каждый сработавший эксплойт сохраняется в `/var/log/reflex_exploits.jsonl`.
- **Защита своего бокса.** Отдельный контейнер с лимитами cgroup, пул воркеров с bounded
  queue, rate-limit на жертву (он же дедуп под флудом), таймауты, circuit breaker по loadavg,
  блэклист инфраструктуры.

## Быстрый старт

### Тестовый полигон (всё в Docker)

```bash
docker compose build
docker compose up -d                 # геймсервер, вулнбоксы, атакующие, REFLEX
docker compose logs -f reflex        # контр-удары и выученные паттерны
docker compose exec gameserver wget -qO- http://127.0.0.1/scoreboard
docker compose down
```

### На своём вулнбоксе

```bash
sudo SELF_IP=10.60.13.1 GS=10.60.254.1 IFACE=eth0 python3 reflex/reflex.py
```

| Переменная | Назначение | Пример |
|------------|-----------|--------|
| `SELF_IP`  | IP вулнбокса в игровой сети | `10.60.13.1` |
| `GS`       | адрес геймсервера | `10.60.254.1` |
| `IFACE`    | сетевой интерфейс | `eth0` |

Номер команды и схема сети выводятся из `SELF_IP`. Подробности, опции и диагностика —
в [QUICKSTART.md](QUICKSTART.md).

## Результаты тестов

Сквозной прогон на полигоне из 9 контейнеров (отчёт — [REPORT.md](REPORT.md)):

- счёт REFLEX **41** против 17 / 15 / 12 у соперников;
- независимая сверка: флаг жертвы реально получен и засчитан нам (10 совпадений, 0 ошибок);
- доступность сервиса для чекера — 100 % (SLA 19/19);
- REFLEX самостоятельно выучил 3 формы эксплойта (query / path / body);
- задержка сервиса p99 < 3,3 мс под флудом; контейнер в лимите 0.5 CPU / 256 МБ.

## Устройство

| Каталог | Что это |
|---------|---------|
| `reflex/`     | сама система контр-удара |
| `svc/`        | уязвимый сервис `notes` (IDOR) — общий для всех команд |
| `gameserver/` | чекер, flag-id API, приём флагов, scoreboard |
| `attacker/`   | имитация атакующих команд (разные формы эксплойта) |
| `probe/`      | нагрузочная проверка доступности сервиса |

изолированной лаборатории.
